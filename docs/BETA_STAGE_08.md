## Proposed database enforcement

All exposed tables default-deny with RLS plus minimal explicit grants. Ownership is derived from auth.uid(), immutable after insert. Account suspension and explicit beta membership checked server-side. Public taxonomy can be read; no anonymous access to jobs, offers, feedback or private profiles. Discovery returns only matching open requests through a safe projection with no private addresses, contact fields or private images. RLS controls rows, so sensitive columns need separate tables/projections.

Customer owns drafts and sees offers for their requests. Professionals see only eligible discovery data and their own offers; competitors cannot read each other's terms. Selected participants alone see scheduling/messages and private job details as necessary. No self-offers. Server validates active category/coverage and eligibility independent of UI mode. Completed reviews must belong to the job customer; professional responses must belong to its selected professional. Reputation derives from eligible visible reviews, not a writable rating counter.

Administrator assignments belong in an unexposed authorization table with no client writes. Check current membership for each privileged operation, never user_metadata or the mode switch. Admin only on web; require MFA before real moderation use. Scoped case support access is explicit and audited, not blanket message browsing. No self-verification or self-adjudication. Verification policy/document retention requires approval before collecting real evidence.

Mutations such as offer acceptance, scheduling confirmation, state changes and reviews use narrow transactional commands. Lock request/job rows; check actor, expected revision, allowed transition and immutable accepted terms; atomically write event history. Unique selected offer/job, one offer per professional/request, unique review/job, foreign keys and bounds are database constraints. Idempotency keys are owner/operation scoped and reject conflicting payload reuse. Duplicate retries return the same result. Direct table writes cannot bypass command invariants. Privileged helper functions, if needed, pin search_path, validate auth.uid(), revoke PUBLIC execute and expose only minimal authenticated wrappers; no generic SQL execution or client service-role key.

Use timestamp with time zone for events and explicit Africa/Lagos interpretation for date/time scheduling; reject invalid/reversed intervals. Money uses bounded nonnegative bigint kobo (positive offers), JSON payloads are runtime validated and unknown fields rejected. Index ownership, discovery category/area/status and participant/message cursor paths. Append-only audit and accepted terms are not client editable. Version-controlled migrations must be generated with installed CLI help/version checked first, applied to local isolated database and security-tested before the dedicated beta project. CLI v3 changed default targets; never infer the remote from a previous link.
